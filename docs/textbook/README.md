# 教材のMarkdown管理とPDF生成

第1章全体をMarkdownへ移し、章に依存しない変換スクリプトと組版テンプレートを用意しました。元PDFの15〜30ページが対象です。内容・バージョン・画面は現在の教材のままで、Java 21やSpring Boot 4.0.2への改訂はまだ行っていません。

## 編集するファイル

| ファイル | 用途 |
| --- | --- |
| `chapters/01/chapter.md` | 第1章の編集元。本文・見出し・操作手順・JavaとXMLのコード・図版参照 |
| `chapters/01/assets/` | スライドと操作画面のベクター図版、PowerPointの埋め込み原本、元位置再現用の線や枠 |
| `chapters/01/source.json` | 元教材、章の範囲、図版の切り出し範囲と編集元の指定 |
| `chapters/01/source-layout.json` | 取り込み時の書式・文字位置・本文との対応・図版内の文字起こし |
| `../../tools/textbook/book.typ` | 共通の書体、余白、章扉、見出し、本文、操作手順、図版、コードの組版規則 |

本文は84ブロック、図版は15点です。15点のうちスライド6点は、Word内に埋め込まれた `.sldx` 原本も保存しています。コードはJavaとXMLの2ブロックを文字として保持し、操作画面内のコードは画面の一部として保持しています。

本文・コード・図版参照と位置情報を分けたため、ページごとの座標をPythonコードへ書き足さずに章単位で処理できます。次章は別の章フォルダーと `source.json` を用意して取り込みます。

## 生成するPDF

出力先は `output/pdf/textbook/chapter-01/` です。

| ファイル | 内容 |
| --- | --- |
| `chapter-reference.pdf` | 元位置再現版。空白ページを含む16ページ |
| `comparison.pdf` | 左が元PDF、右が元位置再現版の16ページの比較 |
| `chapter-flow.pdf` | 自動組版版。現在の原稿では14ページ |
| `checks.json` | ページごとの文字照合・画素差、自動改ページの検証結果 |
| `pNNN-overlay.png` | 元PDFと元位置再現版の重ね合わせ画像 |
| `pNNN-difference.png` | 画素差がしきい値を超えた部分を黒く表示した画像 |

元位置再現版は、改訂前の見た目を照合するためのものです。文字を画像にする方式ではなく、Markdownから読み取った文字を、保存した元の文字位置・書式に対応させて描画します。図版内の文字は、形が変わらないよう輪郭にしたSVGで保持しています。

原稿を編集すると元の文字位置を使えなくなるため、元位置再現版は変更を検出して停止します。編集後は自動組版版を生成します。古い位置情報を使って修正文を隠したり、切り落としたりしないための区別です。

自動組版版では元の行末やページ境界を外し、文章量で折り返し・改ページを計算します。見出しは次の要素と離れにくくし、操作手順と直後の説明・画面はまとめて移動します。図版と1ページに収まる短いコードも分断を防ぎます。章扉は奇数ページから始まる構成で、扉の後ろの空白ページも自動で挿入します。

## 実行手順

Windowsのフォント、Python 3.12、Pandocが必要です。今回確認したPandocは3.9.0.2です。Pythonパッケージの指定は `tools/textbook/requirements.txt` にあります。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r tools/textbook/requirements.txt

# 元位置再現版・比較版・自動組版版をまとめて生成
.\.venv\Scripts\python.exe tools/textbook/build.py --chapter 01

# chapter.mdを編集した後は自動組版版を生成
.\.venv\Scripts\python.exe tools/textbook/build.py --chapter 01 --mode flow

# 原稿の欠落・ID重複・編集後の改ページをテスト
.\.venv\Scripts\python.exe tools/textbook/test_pipeline.py
```

元位置再現版と比較版の生成には、取り込み時と同じ元PDFが必要です。自動組版だけなら、元のWordやPDFを毎回読み込む必要はありません。必要なフォントはWindowsから作業用フォルダーへ読み込み、フォントファイル自体をGitへ登録することはありません。

新しい章を取り込む場合は次のコマンドを使います。取り込み済みの `chapter.md` は、編集内容を守るため通常は上書きしません。`--force` は原稿・位置情報・図版を元教材から作り直す指定です。

```powershell
.\.venv\Scripts\python.exe tools/textbook/import_source.py --chapter 02
```

## 原稿の編集

既存の `::: {#識別子 .paragraph}` と、その内側の文章を編集します。`[文章]{.s009}` などの指定は取り込み元の書体に対応しています。識別子は既存の対応を保ち、重複させないでください。

自動組版では、次のように段落を追加できます。太字もMarkdownで記述できます。

```markdown
::: {#追加した段落の識別子 .paragraph}

ここに**重要な説明**を追加します。

:::
```

見出しは `.heading`、操作手順は `.step`、コードは `.code` のブロックにします。`source-page` の囲みは取り込み時の出典を示すもので、自動組版ではその位置で必ず改ページする指定にはなりません。

スライド内の図や文章を修正する場合は、保存したPowerPoint原本を編集して、表示用図版を更新する工程が必要です。PowerPointを開いてSVGを自動更新する工程は、今回の変換基盤には含めていません。

## 第1章の比較結果

元位置再現版の全16ページで、本文・見出し・コード・ヘッダー・ページ番号の文字数を照合し、欠落・重複はありませんでした。図版として保持した領域の文字は別に記録しています。操作画面の画像、赤枠、矢印は図版内に保持し、コードの背景や注釈の線も再現しています。

16ページ全体を画像化して比較しました。文字位置と太字の描き方を元PDFから測定したことで、ページ専用の試作より近い再現になっています。残る差は主にSVGへ移した図版の輪郭描画、記号の形状、描画エンジンによる文字の縁の違いです。

`checks.json` の画素差はRGB各成分の絶対差の平均で、0は同じ画素、255は最大差です。白地も含むため、一致率としては扱いません。

自動組版版は14ページで、全文字の数量照合、見出しの取り残し、図版と短いコードの分断、本文のはみ出しを確認しました。今回の原稿では問題は検出されていません。

さらに、18段落を追加するテストでは16ページへ増え、追加文章がそれぞれ1回だけ出力されることを確認しました。既存ブロックの往復照合、IDの重複検出、変更した原稿への古い位置情報の流用防止、Windowsの改行コードでの再生成判定もテストしています。

この基盤で確認した範囲は第1章です。他章の複雑な結合表・画面構成や、長いコードの継続表示、目次・索引・章をまたぐ参照は、全体展開時に共通部品へ追加します。
