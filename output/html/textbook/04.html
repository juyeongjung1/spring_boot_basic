04-explanation-1
コードの読み方
12行目
@Column(name = "emp_name", length = 30, nullable = false)
User テーブルを利用しますので、User エンティティも新しく定義する必要があります。
エンティティの定義については、前の章のProduct とほぼ同じですが、12 行のname 属性を見てください。テーブル内の列名は[emp_name]ですが、Java では通常、変数名の単語ごとの区切りに「アンダースコア(_)」を入れるよりは、大文字と小文字の組み合わせにする、「キャーメルケース」を使います。
よって、テーブル内の列名と変数名に違いが発生したら、明示的にname 属性をつける必要があります。

7行目
public String loginSession(UserForm userForm, HttpSession session) {
 セッションは、HttpSession のインスタンスを利用することで、データをセッションスコープに格納できたり、セッション情報を消したりできます。 Spring のController にURL がマッピングされたメソッドのことを、改めて「ハンドラメソッド」といいます。このハンドラメソッドの引数にHttpSession を指定するだけで、裏でフレームワークが HttpSession のインスタンス生成と、セッション情報の取得を自動で行ってくれます。

04-explanation-7
コードの読み方
4行目
<form th:action="@{/login4}" method="post" th:object="${userForm}">
th:object 属性は、「選択対象オブジェクト」と呼ばれ、フォームのデータをController のオブジェクト（この場合は UserForm オブジェクト）にバインド（結びつけ）するために使用されます。
formタグに記述することで、フォームの入力フィールドの値が、UserForm オブジェクトの対応するプロパティに自動的に格納されます。
つまり、Controller のメソッド内でModel にデータを格納しなくても、Form タグの中で、Thymeleaf 上でデータを受け取れるということです。
フォーム内では、*{...}という選択式を使用して、userForm オブジェクトのプロパティに簡潔にアクセスできます。userForm.empId ではなく、*{empId}だけでアクセスできるようになります。


04-explanation-8
コードの読み方
6行目
<p>社員番号 ：<input type = "text" th:field="*{empId}"/>
th:field 属性は、対応するフィールドの name, id, および value 属性を自動的に生成します。ですので、name、id、value を省略できます。
自動生成されるvalue 属性により、フォーム送信後に入力チェックエラーが発生した場合でも、ユーザが入力した値がフィールドに保持されます。これにより、ユーザは入力値を再度入力する手間を省くことができます。
なお、*{empId}は、userForm オブジェクトのempId プロパティを参照しています。
7行目
<span th:errors="*{empId}"></span></p>
 このコードは、empId フィールドに関連する入力チェックエラーがある場合にエラーメッセージを表示するために使われます。エラーがない場合は、何も表示されません。
フォームを送信したとき、もし empId フィールドの値が入力チェックのルールに違反していれば（例えば、必須フィールドが空である、など）、 <span> タグの中に入力チェックごとのエラーメッセージが表示されます。
