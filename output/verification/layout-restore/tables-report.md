# 表の原本配色・配置の復元調査

対象は7章のネイティブMarkdown表32表・587セルです。配色のある表23表、原本から白黒の表9表をすべて確認しました。PPT内の表は、既存SVGの色を保持するため今回の変換対象に含めていません。

## 実装

追加した `tools/textbook/table_styles.py` は、既存の `source-layout.json` とページ装飾SVGだけを読みます。通常の生成で元Word・元PDFへアクセスしません。元データ・原本位置版の原稿・元SVGは変更していません。

```python
from table_styles import table_paint, table_geometry
paint = table_paint(folder, layout, info, markdown_rows)
geometry = table_geometry(layout, info)
```

`paint` のセルは `fill`, `parts`, `align`, `valign` を持ちます。`parts` は文字列・既存style ID・下線の組です。元の文字列と一致するセルは文字単位の書式を保ち、編集したセルは背景と元セル先頭の基本書式を保って新しい本文を描画します。編集を拒否するガードは設けていません。

`geometry` は元の最小行高 `row_heights`、実測行送り `pitch`、代表文字サイズ `font_size`、左余白 `inset`、セルの揃え方を返します。揃え方は元の文字bboxから判定します。複数行のない表の行送り、左寄せセルのない表の左余白は推測せず `None` を返します。

元の列幅は73.076 / 191.09 / 193.71pt、元の行送りは18pt、本文の代表サイズは10.56pt、左余白は2.04ptです。元の見出しは3セルとも中央、本文は左・上下中央です。

実PDFの修正前・原本・修正後を `table69-color-comparison.png` に保存し、PNGで目視しました。灰色・赤字・赤い下線が復元され、文字末尾も表示されています。修正後PDFの罫線11本は0.65pt、濃い灰色です。この比較画像の時点では中央揃え・最小行高はroot側への統合前であり、配色の確認画像として扱います。

## 照合結果

- 32表すべてで、保存済みSVGから得た背景・文字書式・下線が、原本PDFから一度抽出した照合値と完全一致。
- 元PDFを開く関数を禁止した状態でも32表の復元が成功。
- 全32表で1セルを別の文章へ編集する試験が成功。
- 元文字列と現在のMarkdownの対応で不一致セル0。
- 見出し中央揃えの回帰確認が成功。
- Wordの表は全32表の対応箇所を特定。27表は単純全文一致、2表は同文の表が重複、1表は縦結合セルで読取順が変化、2表はWordの表がPDFの改ページで分割。

第6章 `p197-table02` の1セルだけ、Wordの直接背景指定が `FBE4D5`、原本PDF/SVGの表示が白です。ユーザーの見た目の基準である原本PDFを優先しました。

各表の全配色、揃え、実測値、原本ファイルの保全SHA、照合詳細は `tables-report.json`、`table-geometry-audit.json`、`word-table-shading-audit.json` に記録しました。全体PDFの再生成・コミットはroot担当です。
